## 1. 事实:产品现状

### 1.1 产品与模块

**bcailab** 是跑在 Cloudflare 上的小型工具平台(Remix + Pages/Workers + D1 + R2)。
**English Studio** 是其旗舰产品:一个 AI 英语教练。

| 模块 | 做什么 | 素材模型 | 匿名可用 |
|---|---|---|---|
| **Dictation 听写** | 逐句听音频、打字听写。**确定性**词级 diff 评分 | 仅平台素材 | 是(配额) |
| **Reading 朗读** | 朗读文章,LLM 评估发音/流利度/节奏/清晰度 | 平台素材 **+ 用户粘贴文本** | 试用页 |
| **Writing 写作** | 写作后由教练分轮次反馈 | **仅用户自己的文本,无平台素材** | 试用页 |
| **Translate 翻译** | DeepL 式翻译。**免费获客漏斗** | 无素材概念 | 是 |
| **Speech 语音** | 文本转语音工具 | 用户生成 | 否 |

**商业状态:尚无真实用户,产品未上线。** 这一点对"该投入多少 IA 机制"很关键(§8.3)。

### 1.2 学习者模型(已上线,是本设计的数据基础)

已实现并在生产运行:

- **每次评分后的确定性观测**:写入 `learner_tag_observations`,按一套 **12 个标签的词表**
  (`final_s` 词尾-s、`weak_form` 弱读、`th_sound`、`linking` 连读、`article` 冠词……)。
  听写走确定性 diff(高权重);朗读从 LLM 高亮映射(**降权**)。
- **聚合出的能力画像**:`tag_mastery_json` = `{标签: {掌握度 0-1, 曝光次数, 趋势}}`。
- **CEFR 等级**:`cefr_declared`(用户自选)/ `cefr_measured`(从听写准确率对已知 band 推出)
  / `cefr_measured_confidence`。测量置信度够高时**渐进覆盖**自选值。
- **LLM 只命名,不判定**:后台任务把确定性聚合结果**措辞化**给学习者看,它从不决定弱点是否存在。
- **聚合是节流的**:累计 3 次练习才重算一次,后台执行。

**素材库现状:20 篇**(A2/B1/C1/B2 各 5 篇)+ 约 14 篇用户自建。**这个数字是关键约束**(§2.1)。

### 1.3 现有 IA 的四个结构问题(本设计要解决的)

1. **自定义素材压过平台素材**:Reading 页把"你的文章"排在分级素材库**之上**;
   且左侧栏和目录页**各查一次数据库、各列一遍素材**(字面意义的重复查询)。
2. **进度中心是孤儿**:统一进度页只能从营销落地页进入,不在任何导航里。
3. **模块切换器是平的、且对匿名用户有 bug**:切换器维护了一份**简化的模块列表副本**,
   绕过了落地页的 trial 路由规则——匿名用户从听写页的切换器点"朗读",会被踢到登录页,
   而落地页会把他送进试用页。**同一个用户、同一个模块、两种行为。**
   翻译页根本没有切换器,是个死胡同。
4. **没有任何一层表达学习闭环**,只有工具。

## 2. 假设:本设计据以成立的两个前提(**新**,上一轮评审时不存在)

这两条是产品负责人提出的方向性判断,**尚未实现**。设计据此而建,所以它们是最值得质疑的地方。

### 2.1 假设一:素材量将增长约 100 倍

未来批量生成,使**每个等级都有充足素材**(约 500 篇/band,总量约 2000)。

**这条改变了什么:**

- **"某等级素材练完"从第一周必然事件降级为边缘情况。** 现在每 band 只有 5 篇,
  积极的学习者两次坐下就练完,这曾是设计里的承重问题;500 篇后不再是。
- **引入新问题:浏览压力。** 500 篇的平铺网格无法使用 → 素材库**内部**需要筛选。
- **最重要的推论:推荐从"锦上添花"变成"必需品"。** 20 篇时推荐近乎无意义(5 选 1);
  500 篇/band 时用户**根本无法靠浏览做决定**。

### 2.2 假设二:Writing 也将有平台题库

按 CEFR 分级的写作题库,使三个练习工具**结构对称**:平台素材 + 用户自定义。

**这条改变了什么:**

- Writing 从"不适用本模式"变成"适用",架构上纯赚:**同一个组件模式实例化三次**。
- **但只有素材对称,测量不对称**:写作题目**没有 tag 词表**,不贡献能力画像,
  最多像朗读那样给一个 LLM 判的等级信号。**这是设计中必须显式处理的不对称。**

> **请评审者检验:如果这两条不成立(素材停在 20 篇、写作没有题库),这个设计是否过度建造?**

## 3. 提案的核心:从"工具优先"到"教练优先"

### 3.1 推导(第一性原理)

**前提一 · 产品价值在哪?** 不是"能做英语练习"(廉价且遍地都是),而是
**长期的进步 + 一个了解你的系统**。本产品唯一不可商品化的资产是
**评价函数(grader)** 和 **学习者状态回路**;素材、TTS、编辑器都可替代。

**前提二 · IA 应当表达护城河。** 若可防御的资产是学习者状态回路,
那么信息架构就该让这个回路成为产品可见的主干。把产品呈现为五个并列工具,
表达的恰恰是被商品化的那部分。

**前提三 · 学习者的真实闭环:**

> **继续 / 开始正确的练习 → 立即反馈 → 学习者模型更新 → 需要时查看进步**

*(注:上一版把顺序写成"我在哪 → 练什么 → 练 → 看进步",把数据放在了第一位。
外部评审指出这是 analytics-first,应改为 action-first。已采纳,见 §5.1。)*

**因此**:顶层界面回答"继续什么 / 接下来做什么";工具是"做"的地方;进度数据的职责是
**让推荐显得可信**,不是当门面。

**可证伪的表述:** 如果学习者大多到达时就知道自己要干什么、且不希望被告知,
那闭环就不是主干,一个好的工具菜单才是正解。我们**没有任何使用数据**(§8.3)。

### 3.2 分层

```
bcailab                          ← 所有产品
 └─ English Studio Home           ← 登录后的顶层界面 = dashboard
      ├─ 动作区   继续 / 下一步(首屏顶部)
      └─ 状态区   等级 · 练习量 · 覆盖度 · 能力画像 · 趋势 · 最近
           │
           └─ 工具(下沉一层,通过常驻侧栏进入)
                Dictation · Reading · Writing   ← 分级练习闭环
                Translate · Speech              ← 相邻工具,不在闭环上
                 └─ 素材页(平台素材为主轴)
                      └─ 练习会话(无干扰)
```

## 4. 原型逐屏说明

### 4.1 常驻侧栏(所有页面通用)

**静态列表,无下拉。** English Studio(Home)/ Practice: Dictation·Reading·Writing /
Tools: Translate·Speech / 进入工具后追加该工具的动作。

- **为什么去掉下拉**:下拉存在的理由是省空间;侧栏一旦不列素材,空间就富余了。
  (现有代码里那个下拉还因为容器 `overflow:hidden` 被迫渲染在文档流里而非浮层——
  是控件在跟容器打架。)
- **为什么通用**:侧栏常驻列出所有模块后,Home 正文**不再需要"探索"区**。
- **工具动作按工具而异**:Reading =「+ 添加文本」,Writing =「+ 自定题目」。
  **注意:目前只有 Reading 真正支持"添加素材";Writing 的"+"是新建作品(它没有素材库);
  听写的"自带文本"仍在待办中。** 假设二成立后三者才真正同构。
- **修 bug**:模块列表将抽成**共享的纯数据 registry**(含 `access: public|trial|auth` 字段),
  落地页与侧栏共用一份,修掉 §1.3(3) 的匿名路由漂移。

### 4.2 Home —— 动作区(首屏顶部)

**继续**(有未完成练习时)与**下一步**(推荐)两张卡并排。

- **只给一个推荐**,不是三个:多个同等地位的推荐等于把决策负担还给用户,抵消了推荐的意义。
- **"为什么"折进推荐卡内部**:"这篇里**词尾 -s** 出现得比较密——那是你目前最弱的一项。"
  这正是"进度数据让推荐可信"的落实方式,而不是把进度另立门户。
- **措辞诚实**:matching 服务上线前只说「适合你当前等级 + 一项已测得的弱项」,
  **不能说**「为你的薄弱项定制」——目前没有任何东西按 tag 排序。
- **背后是一个纯函数** `selectStarterPractice()`(确定性、可单测),将来整体替换为 matching 服务。
  现在**不建**推荐服务/仓储层/通用信息流框架。

### 4.3 Home —— 状态区(分区网格,非竖向信息流)

面板:**等级**(含置信度)· **练习量** · **覆盖度** · **能力画像**(12 个标签的掌握度与趋势)
· **准确率趋势图** · **最近活动**。

- **为什么 Home 就是 dashboard**:上一版把进度压成一行 +「详情 →」,
  但详情页指向哪?另开一页就是**把我们正在修的"孤儿进度页"问题重演一遍**。
- **为什么是网格不是竖排**:竖向流暗示"一串同类东西";而这里混了三类
  (动作 / 信息 / 导航)。现在导航进侧栏、动作占首屏、信息以面板铺开,层次断裂是明确的。
- **「覆盖度」面板是专门加的**,见 §4.5 的 bug。
- **冷启动时状态区整个不渲染**,避免满屏"暂无数据"。

### 4.4 Home —— 冷启动

新用户没有等级、没有历史,`resolveCefr` 返回 **null**。此时 Home 不是空的,而是单一强 CTA:

> **先测出你的水平** —— 做一篇听写,约 3 分钟,同时就是一次等级测评。
> [开始听写] [或者自己选等级]

- **为什么是听写**:它是**唯一可靠的测量仪**(确定性评分 + 素材带 CEFR 标注),
  不需要麦克风。这不是"学习只能从听写开始"的判断,所以它是**推荐,不是关卡**。
- **硬规则**:等级为 null 时**绝不**显示成 B1。可以在选材策略里把 null 当 B1 用,
  但界面不能宣称一个尚未确立的等级。
- **依赖**:"自己选等级"需要一个一键选级器。**该 UI 尚未实现**,但数据层已存在且无调用方——
  因此把它纳入本次范围。

### 4.5 素材页(Reading / Writing 同构)

顶部**筛选**(搜索 / 未练·进行中·已完成 / 主题 / 长度)→ **按 CEFR band 折叠分组**,
你的等级默认展开并标记 → 底部**你的文本 / 你的题目**(次级但清晰可见)。

- **卡片状态**:未开始 / 进行中 4/11 / 最佳 86%。**"已完成"是卡片状态,不是独立分区。**
- **筛选是假设一带来的唯一结构性新增**,20 篇时不要建。
- **「+ 添加文本」常驻侧栏,与列表位置解耦**:素材涨到几百篇时,
  页面底部的入口等于不存在。动作要常驻,列表可以次级。
- **全展示 + 折叠,永不锁定。** 反对锁定的理由:
  ① 等级估计**本身是不确定的**,用不确定的估计去锁人是敌意设计;
  ② 学习者有正当理由要简单素材(练流利度)和难素材(拉伸);
  ③ 锁定是游戏化 app 的留存/付费机制,配套的是海量库 + 订阅模型——**我们没有订阅模型**。

  **④ 还有一个更硬的、来自代码的理由——这是设计过程中发现的真 bug:**
  等级置信度 = 练习量 × **band 分散度**(只练 1 个 band 封顶 0.5,而覆盖阈值正好是 0.5)。
  **如果推荐器只喂当前等级的素材,学习者就永远只练一个 band,置信度被死死卡住——
  推荐器的保守把等级估计器饿死了。** 这是两段独立代码之间的反馈回路,单看任一边都看不出来。
  **推论**:推荐策略必须定期探邻近 band(既是给学习者拉伸,也是喂估计器),
  因此 UI 更不能让其他 band 显得"禁止入内"。Home 的「覆盖度」面板就是为了让这件事可理解。

### 4.6 不做"合并的素材筛选面"

一个被否掉的方案:把"平台素材"和"用户自有文本"合成一个带 facet 的统一素材面,
理由是"provenance 只是个技术标签,学习者只关心能练什么"。**否掉了**,因为 provenance
是**能力边界**而非标签:

| | 平台素材 | 用户粘贴的文本 |
|---|---|---|
| 有 CEFR band 与 tags | ✅ | ❌(按既定决策不标注) |
| 能做听写 | ✅ | ❌ |
| 贡献能力画像 | ✅ | ❌ |
| 能被推荐 | ✅ | ❌ |

学习者也许不在乎"谁写的",但一定会察觉一类素材不能听写、练了也不进档案。
而"已完成 vs 未开始"**确实**只是状态——所以它属于卡片,不属于分类体系。

**注意区分两个不同的问题**(容易混淆):
- 自有文本与平台素材合成一个筛选面?→ **不**。
- 平台素材库**内部**需要筛选?→ **100x 时必需**(§4.5)。

## 5. 演进过程:三版之间改了什么、为什么

列出来是为了让评审者知道哪些已经被挑战过,以及被什么理由推翻。

| 版本 | 改动 | 触发原因 |
|---|---|---|
| rev1 | 顶层 = dashboard,顺序为「你在哪 → 下一步 → 探索 → 进度 → 最近」 | 初始提案 |
| **rev1→rev2** | **改为 action-first**;进度降为支撑推荐的证据 | **外部评审**:用户不是来欣赏学习者模型的;护城河不该表现为更多图表。*(初稿作者同时也是学习者模型的实现者,初稿自己标注了"可能偏向做一个展示它的界面"的风险,外部评审独立确认该风险已发生)* |
| rev1→rev2 | 路由改为 `/english` 登录后**重定向**到 `/english/home`,而非同一路由双面孔 | 现有代码已按路径判断是否显示 footer;双面孔会让营销页与应用外壳继续耦合 |
| rev1→rev2 | 侧栏下拉 → **静态列表**;Home 正文去掉"探索"区 | 产品负责人:侧栏既然不列素材,就不需要下拉 |
| rev1→rev2 | 「为什么」折进推荐卡;进度压缩 | 产品负责人:动作与信息竖向混排像信息流,不合适 |
| **rev2→rev3** | **Home 改为分区网格 dashboard**(动作在上、数据在下) | 产品负责人:进度等数据应集中在 Home;但不要竖向信息流。**同时解决 rev2 遗留的"详情页指向哪"** —— 另开页面就是孤儿进度页问题重演 |
| rev2→rev3 | 素材库加**筛选**;band 耗尽**降级** | 假设一(素材 ×100) |
| rev2→rev3 | **新增 Writing 页,与 Reading 同构** | 假设二(写作题库) |

## 6. 已定,请勿重议

1. **Matching(学习者→素材的排序服务)推迟。** 本设计只为它留一个可替换的纯函数接口。
2. **确定性层负责测量,LLM 只负责解释。** 这是全产品的规则。
3. **听写是等级测量仪**,不做独立的分级测试。
4. **一篇素材两种模式 = 完成后的衔接,不是合并页面。**(听写摘要 →「读一遍?」→ 朗读)
5. **Translate 留在 English Studio 内**作为免费漏斗。
6. **不做后台管理系统**(无真实用户、无非工程运营者之前)。
7. **不同内容模型的模块不强行统一外壳**(Translate 无素材、Speech 是工具)。
8. **配色不在本轮范围**:原型全部使用中性占位色。产品当前
   `--accent` 与 `--red` 在浅色模式下**是同一个色值**,主 CTA 与表单错误无法靠颜色区分——
   这是一个**独立的功能色分离任务**,排在本设计之前或并行,故原型刻意不做配色决策。

## 7. 我最想被攻击的问题

### 7.1 ⭐ Home 是不是承担太多了?

rev3 的 Home 同时是**动作入口**和**完整 dashboard**。上一轮评审明确否掉了 dashboard-first,
而 rev3 把完整的数据面板加回了同一个页面,只是放在动作区下方。

**我的辩护是**:action-first 说的是**顺序与视觉权重**,不是"数据不能同页";
且另设一个进度页会重演孤儿问题。**但我不确定这个辩护是否成立**,
也不确定它是否只是把 dashboard-first 换了个空间排法。

请攻击:这是合理的综合,还是伪装过的倒退?

### 7.2 两个假设不成立会怎样?

如果素材停在 20 篇、写作始终没有题库,这套结构是否过度建造?
是否应该**先扩素材库**,等真实浏览压力出现后再设计 IA?

### 7.3 500 篇/band 时,band 还是正确的主轴吗?

原型仍以 CEFR band 作为折叠分组的主轴,主题/长度作为筛选。
但素材极多时,也许"推荐给你"或"主题"才该是主轴,band 退为筛选项。

### 7.4 素材极多时,"只给一个推荐"还成立吗?

"只给一个"的理由是避免把决策负担还给用户。但当库里有 500 篇时,
单张卡 +「换一个」是否显得武断?此时给 3 个带不同理由的选项是否更好?
**这与 §4.2 的既定原则存在张力。**

### 7.5 Writing 的"同构"是真的还是装饰性的?

写作题目与朗读素材不是同类对象(一个是刺激物,一个是消费材料)。
相同的外形是否会让用户**误以为**写作也在贡献能力画像(实际不会)?
IA 对称但测量不对称,这个落差该如何在界面上诚实表达?

### 7.6 冷启动仍依赖尚未实现的选级器

若该 UI 未能一并完成,冷启动只剩"做一篇听写"一条路。这够吗?

### 7.7 我没看见什么?

这个方案内部自洽——而自洽恰恰是盲点得以存活的失效模式。
具体地问:**是否存在既非"工具优先"也非"教练优先"的第三种 English Studio IA 框架,
是我没有考虑到的?**

## 8. 我认为真实存在的风险

1. **Home 过载**(§7.1)——最可能的失败方式。
2. **冷启动头一周很单薄**:学习者模型的输出需要若干次练习才有意义
   (聚合每 3 次才重算、置信度需要 band 分散度)。
   若冷启动 CTA 执行不好,Home 会比工具菜单**更差**。
3. **所有前提都未经验证**:没有用户、没有分析数据。§3.1 是从产品战略位置推理,不是从证据。
   缓解措施是这套改动便宜、分阶段、可回滚。
4. **降低自定义素材的层级是真实的行为改变**:Reading 最初的产品形态**就是**"粘贴你自己的文本"。
   现在生产里约 14 篇用户素材,风险低,但应是有意识的决定而非顺手的副作用。
5. **写作的对称可能误导**(§7.5)。

## 9. 明确不在范围内

- **Matching 服务**(只留接口)。
- **视觉设计**:无配色、间距、组件设计;图表仅为占位。
- **游戏化**:无连胜、徽章、闯关。原型里也**没有锁定**,且 §4.5 给出了反对锁定的理由。
- **扩充素材库本身**(是内容任务,但假设一说明它的优先级会因本设计而上升)。
- **Translate / Speech 的内部形态**,除了给 Translate 一个回到 Studio 的入口。
- **功能色分离与免费入口显性化**(见 §6.8,独立任务)。

## 10. 若方案通过,计划的实施顺序

三个可独立回滚的阶段,**不作为一次性大改**:

1. **导航正确性**:抽出共享 module registry;修匿名切换器的 trial 路由;
   侧栏静态化并加 Home 入口;Translate 加返回入口。**不动页面结构。**
2. **Coach Home**:新建 `/english/home`;`/english` 对登录用户重定向;
   动作区 + 状态区;抽出可单测的 `selectStarterPractice()`;一键选级器;
   旧进度页保留为重定向;所有个性化查询**有上限**,失败时降级为模块启动器,**不能整页空白**。
3. **素材页简化**:Reading 去掉列素材的侧栏(同时消除重复查询);
   平台素材为主轴;自有文本次级;完成状态变为卡片状态。

**必须覆盖的状态**:未登录 / 冷启动 / 有未完成 / 活跃 / 当前等级练完 /
引用的素材已下线 / 个性化查询失败降级。选材策略作为纯函数进单元测试。
